# AIchat

ローカルの [Ollama](https://ollama.com/) を使った、**チャット**と**授業ノート要約**の個人用ウェブアプリ。

自宅PCをサーバーにして、同じネットワーク内のスマホやノートPCからブラウザで使うことを想定しています。会話もノートもサーバー側に保存されるので、どの端末から開いても同じ内容が見えます。テキストは外部に送信されません。

- **依存ライブラリゼロ**のNode HTTPサーバー1本で動きます（`node_modules` はCSSビルド時のみ）
- 静的ページの配信と、Ollamaへの**許可リスト方式**のリバースプロキシを同一オリジンで行うため、CORSも混在コンテンツも発生しません
- ブラウザ側もCDNを使わないので**オフラインで動作**します

> [!NOTE]
> **[デモページ](https://nakano-official.github.io/AIChat/)** で画面と操作だけ試せます。AIは動作せず、あらかじめ用意した文章を再生しています。

## 機能

### チャット (`/`)

- ストリーミング表示、Markdown描画（コードブロックはコピーボタン付き）
- 会話履歴はサーバー保存で**全端末共有**。検索・日付グルーピング・リネームに対応
- 最初のやりとりの後、**AIが会話タイトルを自動生成**（手動で付けた名前は上書きしません）
- 自分の発言を**編集してそこからやり直す**、最後の回答を再生成
- 回答には**生成に使ったモデル名を記録**し、フッタに表示します。後からモデルごとの出力を比較できます
- 思考モデル対応。思考は畳んで表示し、経過秒数と文字数を表示。**タイムアウト**を設けて考え込んだまま返らない状態を回避できます
- **思考の設定はモデルごとに出し分け**。`/api/show` で能力を調べ、選んでも意味のない選択肢は表示しません（下の「思考モードの出し分け」を参照）
- 役割プリセット（システム指示）、モデル・temperature の切り替え
- **検索計画・資料の選別・根拠照合**（APIキー不要）。既定の「🔍 調査」では、ローカルモデルが検索語を作り、読むページを選び、原文の根拠を抽出して回答の各主張と照合します。出典と調査過程は会話に保存されます。
- **モデルの常駐** — サーバーが動いている間だけモデルをメモリに保持し、久しぶりに開いた時のロード待ちをなくします
- 音声入力（Web Speech API。HTTPSが必要）
- 生成が中断・失敗しても、そこまでのテキストは失われません

### 授業ノート要約 (`/notes`)

- テキストやファイルを貼り付けて **AIで要約**。科目別に整理
- 長文はブラウザ側で map-reduce（約6000字ずつ）して、コンテキスト溢れを防ぎます
- **PDF・画像からのテキスト抽出**（デジタルPDFは `pdftotext`、スキャンPDFと画像はOCR）
- 入力停止で自動保存されるクイックメモ、Markdown書き出し

## 必要なもの

| | 用途 | 必須 |
|---|---|---|
| [Node.js](https://nodejs.org/) | サーバー本体（実行時の依存パッケージなし） | 必須 |
| [Ollama](https://ollama.com/) | LLM。`ollama pull` でモデルを取得しておく | 必須 |
| [Poppler](https://poppler.freedesktop.org/) | PDFのテキスト抽出・画像化 | PDFを扱う場合 |
| [Tesseract OCR](https://github.com/tesseract-ocr/tesseract) | 画像・スキャンPDFのOCR | OCRを使う場合 |

CSSを変更する場合のみ、追加で `npm install`（daisyUI / Tailwind）が必要です。

## 使い方

```bash
# 1. Ollama を起動し、モデルを用意する
ollama pull <model-name>

# 2. サーバーを起動する（既定はポート80）
npm start
```

ブラウザで `http://localhost/`（授業サマリは `http://localhost/notes`）を開きます。

Windowsでは同梱の `チャット起動.cmd` をダブルクリックしても起動できます。

> **Node はホットリロードしません。** `src/chat-server.js` を編集したら、必ずプロセスを再起動してください。

### 検索して根拠と照合するチャット

既定の **「🔍 調査」** で、以下を順番に実行します。既存端末も初回にこのモードへ移行します。ボタンでOFFにすると、ウェブ取得・照合を行わない通常の会話になります。

1. 直近の会話と質問から、確認事項と検索語を作成します。
2. 検索結果のタイトル・説明・URLを見て、公式資料・原典・対象時期を優先して読む候補を選びます。指定URLも候補に含めます。
3. ページ本文の関連箇所から原文を抜き出し、引用が本文に存在することをプログラムで確認します。
4. 不足や矛盾を調べ、必要なら追加検索します。最大2巡、検索4回・ページ4件です。
5. 根拠番号付きの下書きを作り、各主張の数値・条件・対象などを根拠と照合します。裏付けがない主張・矛盾する主張・検証結果が欠けた主張は、根拠と照合済みの回答から除きます。根拠不足で採用できる主張がない場合は、一般知識や推測も使う参考回答へ切り替えます。

回答には出典リンクが付き、「調査の詳細」で検索語、ページの選択理由、原文、照合結果、未解決事項を確認できます。履歴を開き直しても残ります。停止は検索中・モデル処理中にも使え、未検証の下書きは表示しません。再生成・発言の編集では改めて調査します。

**AIによる照合は正確さの保証ではありません。** 同じローカルモデルが選別と照合を行うため、資料の解釈や検証に誤りが残る可能性があります。検索失敗・根拠不足・照合失敗の場合も、取得できた本文・検索結果の説明文・モデルの一般知識から参考回答を作ります。「ウェブで十分に確認できていない」旨を回答の先頭に表示し、検証済みの出典は付けません。資料との矛盾が判明し、採用できる主張がない場合は引き続き結論を保留します。創作や雑談など検索に適さない用途にはOFFを使えます。授業サマリ画面は従来どおり元資料から要約します。

検索語はDuckDuckGoへ送信し、制限や取得失敗時はBingへ切り替えます。検索結果を5分間再利用し、DuckDuckGoのアクセス制限検出後は10分間そちらへの再試行を控えます。ページ取得は各サイトへ送信されます。利用した検索サービスも「調査の詳細」に残ります。検索語は画面・履歴・サーバーログに残ります。全文を外部LLMへ送る処理はありません。HTML・テキストを対象とし、PDFやログイン必須・JavaScript必須のページは取得できない場合があります。両方の検索サービスが使えない場合は失敗として扱います。リンク先のHTTPエラー・未対応形式・タイムアウトを区別して表示します。WindowsではNodeの旧TLS互換エラーに限り、OS付属のcurlで証明書検証を維持したまま再試行します。

調査中は段階ごとの進捗を表示し、回答は照合後にまとめて表示します。モデル処理は1段階最大120秒、調査全体は8分で停止します。調査モードは低温度・思考OFF（段階指定型は低）で実行します。設定の温度・思考モードは通常の会話に適用されます。

検証コマンド:

- 「npm test」: ネットワーク不要の回帰テスト。
- 「node tests/live-research.js」: 起動中のローカルサーバー・qwen3.5:4b・実際のウェブを使う確認。結果は追跡対象外の data/research-smoke.json に保存。任意の質問を第1引数、モデルを RESEARCH_MODEL 環境変数で指定できます。

### 外部ツールの配置

PDF/OCR機能を使う場合は、プロジェクト直下に以下を配置します。

```
tools/
├─ poppler/     Poppler 一式（pdftotext.exe を再帰的に探索します）
└─ tessdata/    Tesseract の言語データ（--tessdata-dir に渡します）
```

Tesseract 本体は既定のインストール先を探し、見つからなければ `PATH` 上の `tesseract` を使います。

### CSSの再ビルド

`src/chat.html` / `src/notes.html` のクラスや Tailwind の設定を変更したら、`src/app.css` を作り直します。TailwindはJITで使用クラスのみ出力するため、**新しいクラスを追加したら再ビルドが必須**です。

```bash
npm run css          # 1回だけビルド
npm run css:watch    # 変更を監視して自動ビルド
```

`app.css` は静的配信なので、サーバーの再起動は不要です（ブラウザの再読み込みのみ）。

## セキュリティ上の注意

> [!IMPORTANT]
> **このアプリには認証機構がありません。** `0.0.0.0` で待ち受けるため、**到達できる人は誰でも全ての会話とノートを読み書きできます。**
>
> インターネットに直接公開しないでください。localhost、または [Tailscale](https://tailscale.com/) のようなプライベートネットワーク内でのみ使うことを前提にした設計です。信頼できないネットワークで使う場合は、リバースプロキシ等で認証を追加してください。

そのうえで、以下の配慮はしています。

- **許可リスト方式のプロキシ** — Ollamaへ中継するのは `/api/tags`・`/api/version`・`/api/show`・`/api/ps`・`/api/chat`・`/api/generate`・`/api/embeddings` のみ（`/api/show` と `/api/ps` はモデルの能力と配置を読むだけの参照系）。モデルの削除やpullといった管理系エンドポイントは403で拒否します
- **受信サイズの上限** — アップロードとJSONの双方に上限があります
- **Originヘッダの除去** — Ollamaのオリジン保護に弾かれないよう、中継時に `Origin` / `Referer` を落とします
- **アトミックな書き込み** — ノートと会話履歴は一時ファイル＋`rename` で書き込み、ロックで直列化するため、中断してもファイルが壊れません
- **XSS対策** — Markdown描画は、HTMLエスケープしてから変換します

## 設計上のメモ

- **生成系は1並列に直列化** — VRAMの小さいGPUでは複数の生成を同時に走らせると詰まるため、`/api/chat` と `/api/generate` はサーバー側のキューで順番に処理します。複数端末から同時にアクセスしても安全です。軽量なGET（`/api/tags` など）はキューを通しません
- **クライアント切断の検出** — `res` の `close` イベントで検出し、上流のOllamaの生成も止めます。`http.IncomingMessage` の `aborted` イベントはNode 17で非推奨になり新しいNodeでは発火しないため、これに頼ると「停止」してもGPUが回り続けます
- **JSONストアの共通化** — ノートと会話履歴は同じ読み書き・ロック実装を共有しています
- **ウェブ取得はSSRF対策つき** — `/web/api/*` はこのアプリで唯一の外向き通信です。ループバック・プライベート・link-local・CGNAT の各アドレスと `.local`/`.internal`、および http(s) 以外のスキームを拒否します。受信は3MB、タイムアウト15秒、リダイレクトは4回までで打ち切ります。ただし名前解決後のIPまでは検査していないため、DNSリバインディングは防げません
- **モデルの常駐は「保持時間の延長」で行う** — Ollamaは独立したサービスとして動くため、`keep_alive` に無期限を指定すると、このサーバーを止めた後もモデルがメモリに残り続けます。そこで短い保持時間を定期的に延長する方式にしました。サーバーが止まれば延長も止まり、モデルは自然に解放されます（強制終了された場合も同じ）。延長には空プロンプトのリクエストを使います。これはロードのみ行い、生成はしません
- **調査モードは段階ごとに構造化出力** — 検索計画→候補の選別→原文の抜粋→不足時の追加検索→回答→主張単位の照合。小型モデルへの入力と出力を絞り、URLは検索候補・ユーザー指定URL、根拠は取得した原文に制限します。
- **文字コードの自動判別** — 日本語サイトには Shift_JIS や EUC-JP が残っているため、`Content-Type` と `<meta charset>` を見て復号します

### 思考モードの出し分け

`think` パラメータの効き方はモデルごとに違い、**送っても無視される組み合わせがあります**。そこで `/api/show` の結果からモデルを3つに分類し、選択肢を組み立てています（結果はモデル単位でキャッシュします）。

| 分類 | 判定方法 | 実際の挙動 | UI |
|---|---|---|---|
| 非対応 | `capabilities` に `thinking` が無い | `think` を送ると400 | 隠す |
| ON/OFF型 | `thinking` はあるが `{{ .ThinkLevel }}` は無い | `think:false` で思考が止まる。`"low"`/`"medium"`/`"high"` を送っても `true` と同じ | GPUに載る時だけ（下記） |
| レベル型 | テンプレートが `{{ .ThinkLevel }}` を参照 | **`think:false` を送っても思考をやめない**。`"low"` で最小になる | `低`/`中`/`高`（**OFFは出さない**） |

モデル名では判定していないので、新しいモデルにもそのまま追従します。判定に失敗した場合はON/OFF型として扱います。

ON/OFF型については、さらに**モデルがGPUに全部載っているかどうか**で表示を決めます。VRAMに収まらず一部がCPUで動く状態になると、思考が終わって回答が始まるまでの時間が一桁伸び、タイムアウトが先に作動して実用になりません。配置は `/api/ps` の `size_vram` と `size` を比べて実測し、ブラウザ側に記憶します（未計測のうちは表示し、生成が終わるたびに判定を更新します）。レベル型は思考量そのものを指定できるため、この判定は適用しません。

モデル名やパラメータ数では判断していません。**同じ世代・同じ型でも、VRAMに収まるサイズかどうかで実用性が変わる**ためです。

> 思考モデルは `num_predict` が小さいと**思考だけで打ち切られて本文が空になります**（`done_reason` が `length`）。本文が出ない場合はまず出力上限を疑ってください。

## 構成

```
.
├─ src/
│  ├─ chat-server.js       サーバー本体（配信・プロキシ・API・ファイル抽出）
│  ├─ chat.html            チャットUI（単一ファイル）
│  ├─ notes.html           授業サマリUI（単一ファイル）
│  ├─ shared.js            Markdown描画・クリップボードの共有ユーティリティ
│  ├─ app.css              ビルド成果物（npm run css で生成）
│  └─ tailwind-input.css   CSSのビルド元
├─ data/                   ノート・会話履歴・ログ（自動生成／リポジトリ対象外）
├─ tools/                  Poppler・Tesseractの言語データ（リポジトリ対象外）
├─ demo/                   GitHub Pages 用デモのビルド（本体からは参照されません）
├─ tailwind.config.js
├─ package.json
└─ チャット起動.cmd         Windows用の起動ショートカット
```

### APIの一覧

| パス | 内容 |
|---|---|
| `GET /` `GET /notes` | 各UIの配信 |
| `GET /app.css` `GET /shared.js` | 静的アセット |
| `/api/*` | Ollamaへのリバースプロキシ（許可リスト方式） |
| `/notes/api/{list,get,save,delete}` | ノートの永続化 |
| `POST /notes/api/extract?name=<filename>` | PDF・画像からのテキスト抽出 |
| `/chats/api/{list,get,save,delete}` | 会話履歴の永続化 |
| `GET /warm/api/set?model=<name>` | 選択中モデルの常駐を指示 |
| `GET /web/api/search?q=<query>` | ウェブ検索（DuckDuckGo） |
| `GET /web/api/fetch?url=<url>` | URLの本文抽出 |
